# Aike · Echo 内容管理器

运行：

```bash
npm run manage
```

工具只监听 `127.0.0.1:4173`，不会被 Hexo 发布到线上。它负责维护：

- 文章标题、作者、简介、分类与标签
- 首页置顶文章
- 声像节目的标题、简介、日期、封面、链接与标签
- 声像页置顶节目

文章修改会同时写入 `source/_data/archive.yml` 和对应的 `source/_posts/*.md` Frontmatter；DOCX 重新转换时，持久配置仍以 `archive.yml` 为准。

## 保存与恢复

- 保存前会检查配置和文章是否被其他窗口或程序改动。有冲突时拒绝覆盖，表单里的修改仍保留。
- 配置与全部待同步文章先校验，再一起写入；中途写入失败会回滚本次已经写入的文件。
- 每次保存前的版本位于项目根目录 `.content-backups/`。其中 `manifest.json` 记录原路径和对应的 `.bak` 文件。恢复前请先停止管理器和 Pipeline，再按记录恢复需要的文件。
- 备份只在本地保存，不会发布到网站或 GitHub；需要时可自行归档旧备份。
- 保存期间暂时禁用表单，避免正在输入的新内容被保存响应覆盖。

## 文章身份

`archive.yml` 的文章记录增加了固定 `id` 与 `post_file`，文章头部有对应的
`article_id` / `source_key`。不要随意修改这些字段。修改显示标题不会改动旧文章 URL，
也不会让按 pathname 关联的评论失去归属。

源 DOCX/MD 改名时，将配置中的文章键同步改成新文件名（不含扩展名），但保留原来的
`id` 和 `post_file`。首页置顶键也需要同步修改。工具不会再按“同一天”猜测对应文章。
